## Contract and parity

The public additions are `Scanner::stream`, `Scanner::stream_with_limits`,
`StreamSession`, `StreamLimits`, and non-exhaustive `StreamError`. Sessions accept
bytes synchronously; consuming `finish` is the only report-returning operation.
Failure makes execution terminal and discards working output. Existing Scanner
methods, public report data and adapter APIs are preserved.

`ScanReport` stores only `findings` and `candidates`. Findings reuse the shared
whole-source normalization and metadata; candidates use the existing structural
predicate and shared overlap suppression. All report accessors, iteration,
Display and serde output derive from those two exactly compared fields. Source
identity and source-byte totals in batch orchestration are not report fields.
No report field is intentionally omitted and no complete source is retained to
manufacture parity.

Full `ScanReport` equality is verified against `Scanner::scan_source()` through
its public `scan` entry point. The campaign extends prior contextual fixtures to
check the public streaming report, exercises all 44 validator dispatch kinds,
and positively qualifies the three individually admitted built-ins. The 44-kind
matrix includes rejected inputs; it does not claim 44 positive fixtures or full
catalog admission. Existing validator positive tests remain authoritative.

Coverage includes every two-way split of small fixtures, one-byte and multibyte
UTF-8 partitions, deterministic irregular partitions, CR/LF/CRLF, source start
and EOF, delayed validation, empty/projected captures, literal/prefix/suffix/
bounded-regex engines, exact-span priorities and duplicates, partial overlaps,
structural placeholders/boundaries/suppression, oversized suffix tokens,
long-lived simultaneous prefixes and large single callbacks.

The former 1006-test baseline was not used as a substitute for report parity.
All complete built-in portfolios remain unsupported; see
[the rule-level inventory](streaming-compatibility.md).

## Resource evidence

Limits are independent, optional and unlimited by default. Raw rule emissions
count before validation, including rejected candidates. Retained finding and
review records share a separate preventive result count. Normalization and
suppression do not refund it. EOF-only emissions consume the same limits.

The public static requirement adds checked contextual planning metadata,
per-pattern execution metadata, per-rule coordinate cursors, fixed structural
detection state and UTF-8 carry to the existing matcher/context/coordinate plan.
Raw SourceSession admission remains matcher-only and unchanged. The annotated
path's newly retained coordinate metadata is included before allocation.

Representative measured logical high-water marks (native 64-bit host):

| Component | Observed maximum | Planned bound |
|---|---:|---:|
| Validator history | 4,112 bytes | 4,115 bytes |
| Assembly scratch | 5,095 bytes | 8,194 bytes |
| Pending snapshots combined | 4,596,000 bytes | 67,162,120 bytes |
| Pending literal records | 500 | 4,098 |
| Pending projected records | 500 | 4,099 |
| Coordinate history | 16 bytes | 19 bytes |
| Active prefix coordinate pins | 1 | 1 |

These values come from `annotated_retention_high_water_stays_within_checked_plans`
using 1-, 7-, 127-byte and whole-source callbacks. The structural detector uses
fixed arrays of 21 byte slots and 21 scalar-start coordinates, independent of
source size. Existing bounded matcher capacity/length regression tests remain.

`dense_coordinate_lookup_uses_per_rule_cursors_and_linear_work` measures 199,997
coordinate advancement bytes for 100,000 source bytes and three rules, including
an unrelated regex bound of 100,000 bytes. Per-rule monotone cursors avoid both
per-hit callback-prefix replay and coupling dense literal work to that bound.
Historical lookup only traverses rule-bounded retained history.

Pending capacity remains `A + C + 1`: complete match starts are distinct,
projected starts need not be; ready records resolve against full callbacks
before insertion, and EOF emissions validate immediately. Tests verify capacity
and snapshot bounds without requiring a raw-candidate budget.

Spare capacity, allocator overhead, compiled automata, fixed container metadata
not explicitly accounted, regex/validator workspace and output record storage
remain outside logical executor admission. Output vectors belong to the session
until report transfer and have their own record limit. Finalization can hold both
annotated and public representations temporarily. Neither accounting nor
`reserve_exact` establishes a total heap-memory cap. Allocation failure is not a
recoverable custom-allocator contract.

## Remaining release gates and limitations

- PR #36 must be integrated through the ruleset and the resulting main commit
  verified before tagging. Historical main CI is not a substitute.
- Complete Core, Personal, Financial and Combined portfolios fail streaming
  admission. No fallback, regex expansion or catalog rewrite was introduced.
- This is completion-oriented streaming: result metadata may grow with output
  when limits are unlimited. Applications requiring bounded output must configure
  the result limit; the raw candidate limit has different semantics.
- No asynchronous interface, language-specific streaming binding, pre-EOF ordered
  output, source excerpts or universal heap-memory guarantee is provided.
- Version and documentation are prepared for 0.5.0; publication and release tags
  remain outside this execution. Existing interface workstreams are independent.
