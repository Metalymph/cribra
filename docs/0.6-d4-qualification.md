## Implementation and qualification

The public opaque session exposes construction, revisioned replacement edits and
borrowed source/report access. Shared matching kernels emit fallibly before
incremental accumulation, including Prefix/Suffix/regex/per-rule prefilter and
projected captures. There is no incremental raw candidate collection. Shared
validation and normalization/coordinates/suppression remain authoritative.

All controlled source, metadata-array, cache, structural staging, projection and
report allocations have preventive logical reservations. Old and staged cache
records coexist and count; compiled metadata is shared and excluded. A structural
span's cache identity transfers to its materialized record without a second
cache ticket. Span/output buffers still have separate simultaneous byte charges.
The operation guard remains alive through commit and staged cleanup.

The four limits have independent contracts: raw emissions per operation, peak
cache ownership, result materialization before structural suppression, and peak
conservative transaction payload. Suppression refunds no materialization tickets;
normalization losers and rejections remain in cache accounting. Old report arrays
are charged storage bytes, not new-operation result tickets.

## Resource ownership evidence

These are separate private diagnostic fixtures: one sparse literal, one dense
self-overlapping literal, and structural-only detection. Each inserts one byte
near the middle. Byte values are logical payload, not heap allocation sizes.
Observed values are maxima at explicit ownership checkpoints. Conservative
reservations additionally cover construction/Box conversion destinations and
buffer coexistence between checkpoints; allocator relocation is not measured.

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Sparse literal | 66,007 | 66,190 | 132,309 | 132,253 | 2 | 11 | 41 | 1 |
| Dense literal | 65,537 | 9,502,616 | 15,335,113 | 11,665,209 | 131,069 | 3 | 41 | 65,534 |
| Structural | 65,521 | 380,016 | 655,105 | 550,305 | 6,551 | 0 | 41 | 3,275 |

Tests reconcile the final live ledger exactly with old snapshot + shared session
plan + staged snapshot, after scratch ownership is released. Exact reserved byte
budgets succeed and one-byte-lower budgets fail both construction and edits.
These fixtures measure zero revalidation/regeneration/fallback; other tests
exercise those paths and their raw budget semantics. Cache capacity is never
substituted for logical length.

The accounting excludes spare capacity, allocator overhead/reallocation machinery,
fixed stack/state metadata, shared compiled automata/rule strings, regex search
caches and capture workspace, caller input and report clones. Existing validator
workspace also remains excluded: lowercase/context strings, decoded/re-encoded
base64 or base32 credentials and parsing scratch. Such allocations can occur
before cache insertion and can depend on candidate extent. All new controlled
incremental temporary buffers are charged; this is not a total heap-memory cap
or allocator-failure recovery guarantee. See [the full contract](incremental.md).

## Measured performance

Machine: Apple M3 Pro, 11 cores (5 performance + 6 efficiency), 18 GB RAM,
macOS 27.0.1 (26A434), aarch64-apple-darwin. Rust 1.99.0
(`b940084d7`, LLVM 23.1.1), Cargo's default optimized bench profile, all features.
The MSRV checks used 1.97.0; benchmark measurements used stable 1.99.0.

Commands:

```sh
cargo bench --bench incremental --all-features -- --test
cargo bench --bench incremental --all-features -- --noplot
cargo test --all-features --lib incremental_session -- --nocapture
```

No concurrent qualification/build campaign ran during measurements. Scanner
compilation and initial state preparation were excluded. Each primary path
creates the same replacement document and drops the old source/report at commit.
Parity assertions were untimed. Updates used 50 samples, 3-second warmup and an
8-second target; reference/sequence groups used Criterion's 100 samples and
5-second target. These are local measurements, not portable guarantees.

Sparse literal and structural workloads improve materially here. Dense duplicate
literals are approximately 3.92× slower incrementally. The implementation still
traverses/stages every surviving cache record and globally normalizes grouped
records despite a tiny local matcher span; timing was not decomposed by a
profiler. Mixed and contextual rows have slightly higher incremental means;
their intervals must be consulted before claiming a stable regression. Built-in
portfolios and whole-document replacement are near parity. No slow workload was
removed, and no localization or indexing was added to hide these outcomes.
