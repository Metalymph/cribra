# Core 0.5.0 release preparation

## Scope and versions

Core `cribra` is 0.5.0 with Rust 1.97 MSRV. CLI remains 0.4.4, WASM 0.4.5,
and the non-published C adapter 0.3.0. CLI and WASM require core `0.5`; C uses
the workspace path. Cargo.lock changes only the core version, with no new or
upgraded third-party dependencies. MIT license, repository and documentation
URLs remain unchanged. Packaging verifies source, README, license and docs.

Implementation is complete for explicitly admitted configurations. This includes
full report parity, arbitrary UTF-8 transport partitions, contextual validation,
exact coordinates, structural review detection, three independent optional
limits and terminal failures, without retaining the complete source. Complete
built-in portfolios remain unsupported for streaming. Logical storage admission
is not a total heap-memory guarantee.

## Integration

The release campaign uses `feature/v0.5-d5-streaming` and a PR into `main`.
All incoming working-tree changes belong to the streaming campaign and are
preserved in that integration; no matcher or validator development is added by
release preparation. Existing workflows and independently versioned adapters
are not redesigned. Required checks and native ABI gates must qualify this PR,
not merely the older main revision. The qualification ledger records evidence.

Merging is a separate integration operation, through the active ruleset. Verify
the resulting main commit and its CI before treating it as the release commit.
No tag is created or pushed by this preparation.

## Automated publication

`.github/workflows/release.yml` triggers on tag pushes matching `v*.*.*`. Its
exact version check requires `v0.5.0` for this core. The workflow validates and
packages the tagged source, performs a publication dry run, publishes only
`cribra` through crates.io OIDC in environment `release`, then creates the
GitHub Release. No adapter is published by this tag. Ordinary main pushes and
PR merges do not publish. WASM tags use a separate `cribra-wasm-v*` workflow.

Only after explicit publication authorization and qualification of the merged
main commit, the final operations are:

```sh
git tag -a v0.5.0 <qualified-main-commit> -m 'Cribra 0.5.0'
git push origin refs/tags/v0.5.0
```

The second operation triggers publication; it is not part of preparation. Before
running it, verify tag absence, exact core version, clean release tree, checked
main ancestry, green required CI and native ABI gates, and no release blockers.
Observe `Release` through all three jobs and confirm crates.io and the generated
GitHub Release. Never duplicate those publication operations manually.
