# Cribra v0.7 — Configuration Qualification

Date: 2026-10-15

## Supported profiles

| Profile | Rust core | WASM adapter |
| --- | --- | --- |
| Core | Scanning, reporting, streaming, incremental scanning | Scanning and reporting |
| Flow | Core + transformations | Core + transformations |
| Fuse | Flow + parallelism and Serde | Not supported |

Flow is the default configuration for Rust and WASM.
Flow is also the official WASM distribution profile.

### Cargo configuration

| Profile | Rust | WASM |
| --- | --- | --- |
| Core | `--no-default-features` | `--no-default-features` |
| Flow | Default features (`transform`) | Default features (`transform`) |
| Fuse | `--all-features` | Not applicable |

Profiles are documented combinations of existing Cargo features,
not additional Cargo features.

## Runtime qualification

The WASM qualification runner builds both supported profiles,
generates JavaScript/TypeScript bindings and executes Node.js
runtime smoke tests.

Validated behavior includes scanning, findings, candidates,
explanations, reporting and API signatures.

Core excludes all six transformation methods.
Flow exposes and executes all six transformation methods.

Command:

`node crates/cribra-wasm/tests/runtime/qualify.mjs`

The release workflow explicitly qualifies Flow.

## Limitations

- These are local measurements, not release-size guarantees.
- Measurements depend on the compiler, target, profile and tools.
- Rust measurements use a scanning-only consumer.
- Browser integration is not covered by the Node.js smoke tests.
- Optimized production WASM artifacts are measured separately
  from the runtime qualification builds.
- Full repository regression and release publishing are separate
  qualification steps.
